Feature Flags

Creating your first feature flag

Feature flags let you enable or disable features for specific users or groups without deploying new code. This guide walks you through creating and using your first flag.

1. Create a flag

  1. Navigate to Feature Flags in the sidebar
  2. Click New feature flag
  3. Enter a key (e.g., new-checkout-flow)
  4. Set your release conditions

2. Add release conditions

Release conditions control who sees your flag. You can target by:

  • Percentage rollout (e.g., 25% of users)
  • User properties (e.g., email contains @company.com)
  • Geographic region (e.g., $geoip_country_code = "US")

3. Check the flag in your code

import posthog from 'posthog-js'

// Boolean flag
if (posthog.isFeatureEnabled('new-checkout-flow')) {
  showNewCheckout()
}

// Multivariate flag
const variant = posthog.getFeatureFlag('checkout-button-color')
if (variant === 'blue') {
  setButtonColor('#0000FF')
}
Note: Feature flag evaluations count toward your MTU (monthly tracked users) limit, regardless of whether the flag returns true or false.

4. Local evaluation (optional)

For server-side flags, use local evaluation to avoid an API call on every request. The SDK downloads flag definitions and evaluates them locally.

const client = new PostHog('phc_...', {
  host: 'https://app.posthog.com',
  personalApiKey: 'phx_...',  // enables local evaluation
})

// Evaluates locally — no network call
const enabled = await client.isFeatureEnabled(
  'new-checkout-flow',
  'user-123'
)
